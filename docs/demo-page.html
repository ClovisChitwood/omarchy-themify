Why the plain page still wins

By A. Sample · 14 March

Every few years the web decides that reading was the boring part. This time the argument is about colour: whose palette a page belongs to — the one it shipped with, or the one the rest of your machine is already using.

Most pages never answer the question. They are written for a white canvas, with the ink set per element and no thought given to anything else. Hand that page a dark canvas and the layout survives, the images survive, and the words quietly vanish.

“It rendered fine in my browser” is a statement about one browser, on one machine, with one set of colours.

What actually breaks

It is rarely the stylesheet. A page that ships a real stylesheet can be recoloured from outside, because the rules are visible and overridable. The trouble is the ink nobody wrote down in a rule:

<p style="color:#333">text that assumes a white page</p>

Measured on a sample of 400 pages

Hardcoded ink on every text node61%
Ink set inline, per element38%
Declares its own dark mode27%

The fix is smaller than it sounds

You do not have to rewrite the page. Find the text that no longer reads, work out what is actually behind it, and move that text's colour the shortest distance that makes it legible again. Everything else — the layout, the images, the type — stays exactly where the designer put it.
